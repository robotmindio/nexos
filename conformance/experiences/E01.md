# E01 — Branch, validate and selectively promote managed work

Qualification: not implemented. This is an acceptance specification, not a record of an executed test.

## Given

A real managed workspace contains source/configuration, artifact files and one service or checkpoint-aware data resource. Its base revision, protected data and excluded host scope are recorded. A human has bounded authority to create a branch and propose promotion.

## When

**E01-T1.** Inspect the managed/excluded manifest, create a branch and change the service/configuration plus an artifact in isolation.

**E01-T2.** Run actual validation and review a semantic diff showing touched resources, effects, expected revisions and recovery limits.

**E01-T3.** Promote the selected change using a reviewed plan bound to the current base; inspect per-provider stages and the resulting artifact/service behavior.

**E01-T4.** Complete the same deterministic operations from CLI and shell with model access disabled.

## Then

The branch’s protected base and unmanaged host data remain unchanged until an explicitly permitted promotion. Successful promotion has receipts and real postconditions. Selective promotion never silently copies unselected side effects.

## Required negative and interruption paths

**E01-N1.** Modify the base after validation: promotion conflicts and stale approval cannot overwrite the change.

**E01-N2.** Crash after each provider stage: show committed, pending, compensated or unknown states and execute the documented recovery.

**E01-N3.** Attempt filesystem escape and restore an application-incompatible checkpoint: both fail at their actual boundaries.

## Evidence

Before/after managed manifests and digests; actual service observation; revision/approval identities; provider stage receipts; crash injection and recovery transcript; excluded-data comparison.

Use the environment/claim rules in [ACCEPTANCE.md](../ACCEPTANCE.md). The implementing package supplies executable commands and assertions as the real implementation is written; no illustrative command here is represented as an existing CLI.

## Variants and guarantee limits

Baseline is local managed scope. Whole-host generations and installation recovery belong to E10; external-world effects are never covered by a universal undo claim.

## Coverage

Contributing packages: P03, P05, P11, P14. Invariants: I01, I04, I05, I06, I08, I09, I14, I20. A contributor list is not a requirement to complete every extension before the baseline variant can qualify; each release profile selects its exact prerequisites and variant.
