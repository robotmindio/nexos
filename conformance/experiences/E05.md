# E05 — Inspect observed lineage and correct derived memory

Qualification: not implemented. This is an acceptance specification, not a record of an executed test.

## Given

A real workflow has produced an artifact from authorized inputs through recorded effects. Some relationships are observed and others are assertions/inferences. Optional semantic indexing has explicit ownership and retention contracts.

## When

**E05-T1.** Select the artifact, inspect its digest, producing execution, actor, authority, inputs and effect receipts.

**E05-T2.** Traverse lineage and inspect source freshness and claim classification.

**E05-T3.** Correct a derived claim, rebuild the relevant projection and export the authorized lineage.

**E05-T4.** Remove source access or delete a payload according to policy and inspect all relevant projections.

## Then

The system explains recorded history without inventing missing evidence. Corrections alter derived knowledge without rewriting permitted historical facts. Current authorization applies to retrieval and export.

## Required negative and interruption paths

**E05-N1.** Corrupt an artifact or withhold a parent record: digest mismatch/missing evidence is explicit.

**E05-N2.** Query a stale semantic index after revocation: private payloads cannot leak through cached retrieval.

**E05-N3.** Disable telemetry or the optional semantic service: durable receipt inspection remains available while richer retrieval reports its actual state.

## Evidence

Real artifact bytes/digests; lineage query results; observed/asserted/inferred labels; access denial; deletion/tombstone and reindex results; export inspection.

Use the environment/claim rules in [ACCEPTANCE.md](../ACCEPTANCE.md). The implementing package supplies executable commands and assertions as the real implementation is written; no illustrative command here is represented as an existing CLI.

## Variants and guarantee limits

P01 provides basic receipts and P05 inspection; the full knowledge/projection behavior requires P08 and any specifically claimed real NoemaDB adapter.

## Coverage

Contributing packages: P01, P05, P06, P08, P10, P13, P14. Invariants: I08, I09, I11, I13, I16, I19, I20. A contributor list is not a requirement to complete every extension before the baseline variant can qualify; each release profile selects its exact prerequisites and variant.
