# E10 — Install, update, back up and recover without corrupting work

Qualification: not implemented. This is an acceptance specification, not a record of an executed test.

## Given

A specific runtime or distribution release profile names supported upgrade paths, system/runtime/data versions, backup scope and a tested recovery route. The test uses actual artifacts and a clean target environment.

## When

**E10-T1.** Install the submitted build, create managed work and verify an application-aware backup/checkpoint.

**E10-T2.** Upgrade from a prior qualified compatible build with documented preflight and migration steps.

**E10-T3.** Interrupt update/restore at declared boundaries and use the documented recovery path.

**E10-T4.** Verify artifact/data integrity, task/authority state and ordinary no-model usability after recovery.

## Then

Recovery restores only its declared scope and compatibility. Configuration generations, database schema and secret/grant state are handled distinctly. A failed migration is not concealed by a successful boot.

## Required negative and interruption paths

**E10-N1.** Attempt incompatible data downgrade, corrupted backup/image and untrusted update provenance.

**E10-N2.** Exhaust storage or interrupt after a generation switch but before a data migration completes.

**E10-N3.** Restore expired/revoked credentials or access an export beyond its scope: the declared policy remains enforced.

## Evidence

Build/image hashes and tuple; prior/new versions; real installation/update/recovery commands; checkpoint/backup digests; data compatibility results; failure injections and post-recovery E08 checks.

Use the environment/claim rules in [ACCEPTANCE.md](../ACCEPTANCE.md). The implementing package supplies executable commands and assertions as the real implementation is written; no illustrative command here is represented as an existing CLI.

## Variants and guarantee limits

Runtime-only lifecycle qualification does not imply bootloader/image qualification. The reference-distribution variant additionally requires P11 and actual VM boot/recovery.

## Coverage

Contributing packages: P11, P12, P14. Invariants: I05, I06, I07, I09, I11, I15, I16, I18, I19, I20. A contributor list is not a requirement to complete every extension before the baseline variant can qualify; each release profile selects its exact prerequisites and variant.
