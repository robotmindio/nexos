# Start a long implementation session

This package does not start an agent, create a scheduled job or authorize external spending. It supplies a concrete implementation mandate that the owner can assign through the chosen coding environment.

## Recommended first assignment

Use M1 as the first implementation scope: P00–P05, ending with a useful local managed workspace. This includes real bounded operation, enforced authority, branch/promotion, durable jobs and a human shell. It preserves the path to the full vision while making the first long assignment finite and independently verifiable.

The following text assumes the user has assigned that scope. Existing explicit permissions in the execution session remain authoritative.

> Implement NexOS milestone M1, packages P00 through P05, in this repository. Read AGENTS.md and the normative contracts relevant to the active package. Inspect the integration evidence and the smallest relevant RobotMind code at its pinned revision before inventing substitutes. Begin with P00 and continue through unblocked work in the assigned scope without ending at commits or intermediate milestones.
>
> Deliver real integrated behavior through CLI and a usable human workspace. Validate failure, isolation, accounting and recovery paths on the declared Linux tuple. Keep model access optional for every M1 operation. Do not replace unavailable integrations with production mocks or claim runtime qualification from specification checks.
>
> Use separate worktrees and clear ownership for parallel implementation. Persist actual commands, environment, revision, evidence and a precise next action in checkpoints. Request independent qualification at package boundaries; if a verifier is unavailable, preserve implemented status and continue independent work. Use the current session’s resource and external-action authority without repeatedly seeking already-granted permission.
>
> Continue until M1 is independently qualified, the assigned resources are exhausted, the user interrupts, or all remaining authorized paths have concrete blockers. Before any technical session limit, preserve a resumable checkpoint. Report the achieved scope and evidence; do not describe the entire NexOS roadmap as complete.

## Subsequent assignments

Select the next named milestone or profile after inspecting actual state. P06 can qualify the `adaptive-ai` profile before generated views, knowledge projections and demonstrations complete M2. Distribution and federation are separate expansions. An accelerator assignment names available physical hardware. An ecosystem assignment names the actual adapters to qualify.

The assigned scope, target tuple, authorized repositories, external actions and budget must be concrete. When the user has already supplied them, retain that authority instead of asking again. When one missing item blocks a particular real-provider test, prepare the test and continue independent work; report the exact remaining decision.

## Before claiming a result

Run the repository’s specification validator, then the actual implementation-specific checks created by the package. The former verifies the specification artifacts; it cannot stand in for the latter. Reproduce the submitted implementation independently under [ACCEPTANCE.md](../conformance/ACCEPTANCE.md), and update only the package/profile states supported by that evidence.
