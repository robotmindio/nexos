# P02 — Enforced authority, delegation and accounting

Status: implementation and qualification pending. Dependencies and coverage are canonical in [plan.json](../plan.json); mutable state is in [state.json](../state.json).

## User-visible outcome

Untrusted workers can perform only declared actions within a measured boundary, and humans can narrow or revoke their authority without relying on model obedience.

## Implementation work

1. Implement deterministic grant validation, bounded delegation, expiration, revocation and review binding. Bind worker identities to actual isolation/transport identities; same-UID clients must not impersonate each other using a body field.

2. Enforce filesystem, process, network and credential boundaries for each claimed profile using qualified host facilities. A capability broker alone does not contain direct syscalls or network egress.

3. Implement atomic budget reservations with explicit units, reservation lifetimes and settlement. Distinguish enforceable hard limits from provider-estimated spend and define overrun liability.

4. Persist revocation epochs and acknowledgements; serialize dispatch against revocation at the enforcement point. Classify already-dispatched effects and pending requests separately.

## Acceptance

**P02-A1.** Authorized operations succeed; direct path traversal, symlink escape, broker forgery, host credential access and undeclared egress fail in the actual claimed sandbox.

**P02-A2.** Child grants cannot increase operation, target, time, delegation depth or budget; concurrent reservations cannot oversubscribe an enforceable parent limit.

**P02-A3.** After revocation acknowledgement no new dispatch is authorized at the controlled enforcement point under that grant; previously dispatched, in-flight or unknown effects remain visible and are reconciled.

**P02-A4.** A changed plan, target revision, capability version or effect summary invalidates an existing approval binding.

**P02-A5.** If a required containment facility is absent, profile admission fails with an actionable diagnosis rather than silently launching an unsandboxed worker.

## Failure and recovery coverage

Race grant revocation, expiry and two concurrent admissions; crash between reservation and dispatch; test a malicious real child process, not only a mocked policy call.

## Scope boundary

Host root compromise, arbitrary kernel exploit resistance and provider costs the provider cannot hard-cap. These are explicit exclusions, never hidden guarantees.
