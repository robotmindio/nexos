# P07 — Safe generated views and compositions

Status: implementation and qualification pending. Dependencies and coverage are canonical in [plan.json](../plan.json); mutable state is in [state.json](../state.json).

## User-visible outcome

A user creates, edits and saves a purpose-built interface that invokes real capabilities and remains usable without its generating model.

## Implementation work

1. Implement the constrained declarative view schema, approved components and typed bindings. Render only authorized data and reference capabilities by explicit version.

2. Build composition validation for input/output compatibility, required authority, effect summaries, budgets and failure handling. Semantic preconditions remain provider-checked; matching types do not prove workflow correctness.

3. Allow direct editing, versioning, export and reopening. Revalidate authority and freshness on each invocation; saved bindings carry no ambient credentials.

4. Use real discovery/context to propose a view, preview its operation and persist the reviewed artifact. Reject executable privileges hidden in generated markup.

## Acceptance

**P07-A1.** E03 generates a useful view over at least two actual capabilities, edits a parameter manually and produces verifiable outputs.

**P07-A2.** Reopening the saved view with inference disabled works for deterministic operations and clearly identifies operations that need inference.

**P07-A3.** Unknown components, undeclared network requests, secret-bearing bindings and incompatible capability versions are rejected.

**P07-A4.** Membership revocation and changed target revisions take effect without trusting cached UI authorization.

**P07-A5.** Keyboard and accessible interaction remain functional after generated layout changes.

## Failure and recovery coverage

Malformed schema, disconnected data source, stale binding, unauthorized target, capability removal and composition partial failure.

## Scope boundary

Arbitrary privileged JavaScript, a new general UI framework or proof that generated programs are correct merely because their schemas validate.

## Handoff and evidence

Record the exact submitted revision, target tuple, commands, exit codes, artifact/receipt digests, observed negative outcomes and reproduction recipe.
