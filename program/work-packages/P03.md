# P03 — Managed workspace branches and promotion

Status: implementation and qualification pending. Dependencies and coverage are canonical in [plan.json](../plan.json); mutable state is in [state.json](../state.json).

## User-visible outcome

A user branches a declared workspace subset, tests changes in isolation, inspects a meaningful diff and promotes validated changes with precise recovery behavior.

## Implementation work

1. Implement branch identity, base/head revisions and a manifest of managed files, configuration and provider checkpoints. Show excluded host/data resources before branch creation.

2. Create isolated branch execution with the declared snapshot/overlay strategy. Quiesce or use application checkpoint protocols when consistency spans a database and files.

3. Implement typed diff and selective promotion. Revalidate the expected base/head, dependency revisions and required tests. Promotion uses per-provider steps and compensations, not an invented global transaction.

4. Persist prepared/committed/compensated/unknown stages so interruption can resume or reconcile without overwriting concurrent work.

## Acceptance

**P03-A1.** E01 performs real dependency/service and artifact changes in the branch while protected base and unmanaged data remain unchanged.

**P03-A2.** Concurrent base edits produce a reviewable conflict; approval for an earlier revision cannot promote the changed plan.

**P03-A3.** Inject failure after each promotion stage. The resulting UI/CLI state identifies which effects committed and which remain pending, compensated or unknown.

**P03-A4.** A database checkpoint restores only under its declared application/schema compatibility rules; Nix generation rollback is not claimed to restore mutable data.

**P03-A5.** An authorized human completes the full flow without a model and can export the promotion receipt.

## Failure and recovery coverage

Branch disk exhaustion, stale validation, symlink escapes, simultaneous promotion, incompatible database restoration and crash during generation switch.

## Scope boundary

Arbitrary POSIX process snapshots, universal database merge, transactions over external services or whole-host undo.
