# P12 — Qualified accelerator and local-inference profiles

Status: implementation and qualification pending. Dependencies and coverage are canonical in [plan.json](../plan.json); mutable state is in [state.json](../state.json).

## User-visible outcome

A specifically declared GPU or NPU profile executes inference with measured scheduling, memory, privacy, cost and recovery behavior.

## Implementation work

1. Select one real available accelerator tuple: device/firmware/driver/runtime/model build and precision. Record licensing/distribution constraints before image redistribution.

2. Integrate the existing inference gateway/provider path and capability contract. Do not build a parallel router to expose hardware.

3. Implement admission and accounting appropriate to real device isolation. Where per-agent hardware isolation is unavailable, use a shared trusted inference service or reject the hostile-workload profile.

4. Measure residency/eviction, out-of-memory recovery, interactive latency, thermal/power constraints and CPU fallback policy. Mark estimates and measured values separately.

## Acceptance

**P12-A1.** E09 completes on the actual named accelerator and compares output/task success, latency and resource usage with the CPU/provider baseline.

**P12-A2.** Concurrent workloads cannot exceed declared enforceable limits; unsupported isolation is shown and not advertised.

**P12-A3.** OOM, worker crash, model eviction and driver failure produce bounded task outcomes and retain correct receipts/liability.

**P12-A4.** E08 and E10 core operation/recovery remain usable when the accelerator is unavailable.

**P12-A5.** The qualified report names exact hardware and model tuple; another accelerator remains unqualified.

## Failure and recovery coverage

No physical runner, device loss, OOM, incompatible driver update, model loading failure and resident-context cross-user leakage.

## Scope boundary

Generic GPU/NPU support from compilation, benchmark-only success without user task evidence or hardware safety guarantees.

Record the exact submitted revision, target tuple, commands, exit codes, artifact/receipt digests, observed negative outcomes and reproduction recipe.
