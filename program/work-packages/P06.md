# P06 — Adaptive AI planning with governed context

Status: implementation and qualification pending. Dependencies and coverage are canonical in [plan.json](../plan.json); mutable state is in [state.json](../state.json).

## User-visible outcome

A real model can inspect authorized state, propose typed work, adapt to an observed failure and produce a verifiable result under the same authority used by a human.

## Implementation work

1. Integrate a named real inference provider via the audited existing gateway path where applicable. Record model/build/provider settings and context, cost and privacy constraints.

2. Assemble context from authorized structured observations with provenance, version, freshness and explicit uncertainty. Separate retrieved content from executable authority.

3. Persist a user-editable plan and dispatch only typed capability requests through deterministic admission. Replan on actual observations; changes to reviewed effects require new binding where policy demands it.

4. Evaluate bounded success, model substitution, injection resistance, failure handling and user intervention. Model-less primitives remain usable while inference-dependent planning reports unavailability.

## Acceptance

**P06-A1.** E09 uses a real model to complete the declared task and adapt to a deliberately changed condition; record actual artifacts, decisions exposed to the user and effect receipts.

**P06-A2.** Untrusted retrieved instructions cannot grant access, exfiltrate secrets or bypass the broker; forbidden effects fail independently of what the model proposes.

**P06-A3.** When context expires, permissions change or the user edits the plan, dispatch revalidates the exact relevant state.

**P06-A4.** The user interrupts and manually completes a step, then resumes the agent without duplicate committed work.

**P06-A5.** An alternate qualified model/provider can execute the same capability contract; failures are measured rather than hidden behind a preferred-model demo.

## Failure and recovery coverage

Malformed model output, no available model, context-window exhaustion, stale observations, prompt injection, provider timeout and budget exhaustion.

## Scope boundary

Claims of general intelligence, guaranteed inference accuracy, automatic trusted memory or real-model success from fixtures.

## Handoff and evidence

Record the exact submitted revision, target tuple, commands, exit codes, artifact/receipt digests, observed negative outcomes and reproduction recipe. Link applicable experiences (E04, E05, E09) and invariants (I01, I02, I03, I04, I08, I11, I12, I13, I14, I16, I18, I20).
